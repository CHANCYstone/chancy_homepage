# ChancyStone · PRD · v1-launch

> 文件位置：`iterations/v1-launch/PRD.md`
> 配合项目根的 BRIEF.md 阅读。这份 PRD 描述本次迭代要做的事。

## 1. 项目背景
ChancyStone 是面向招聘方和行业同行的个人作品集网站，展示跨领域技术背景（量化/AI/写作）与持续学习深度。内容来源于本地 Obsidian vault，通过 GitHub 部署。

参见：[BRIEF.md](../../BRIEF.md)

## 2. 本次目标
第一版上线后，招聘方通过简历/GitHub/搜索引擎进入网站，能快速浏览作品集并找到联系方式。网站同时作为公开知识库，展示 Principles、Writing、量化研究三个方向的思考输出。

## 3. 用户与关键场景

### 场景 1：招聘方评估候选人
- **用户**：HR 或技术面试官，从简历/LinkedIn 上的链接点进来
- **旅程**：进入首页 → 看到定位和技能概览 → 点进作品集浏览 2-3 个项目 → 进入联系页
- **结果**：对候选人能力形成具体印象，通过联系方式发起沟通

### 场景 2：同行了解技术视角
- **用户**：开发者或量化从业者，从 GitHub profile 或社交媒体分享链接进来
- **旅程**：进入首页 → 看到作品分类 → 点进感兴趣的 Principles/量化研究内容 → 阅读详情
- **结果**：了解作者的技术视角和思考体系

### 场景 3：社交媒体品牌展示
- **用户**：任何通过社交媒体分享链接到达的人
- **旅程**：直接进入某个项目/文章详情页 → 浏览内容 → 返回首页了解作者
- **结果**：对作者形成认知，可能关注或收藏

## 4. 页面结构

- `/` — 首页：第一屏传达定位，展示精选作品，引导深入浏览
- `/about` — 关于：个人背景、技能栈、经历、学习体系
- `/projects` — 作品集列表：所有项目（代码项目 + Obsidian 内容）按类别展示
- `/projects/[slug]` — 作品详情：单个项目/文章的完整内容
- `/contact` — 联系：联系方式和社交链接

## 5. 信息架构

### 首页 `/`
- **Hero 区** — 第一屏传达"我是谁 + 我做什么"
  - 内容槽：名字 / 一句话定位 / 主 CTA 按钮（查看作品）
- **精选作品区** — 展示 3-4 个代表性项目，快速建立能力印象
  - 内容槽：每个项目的标题 / 一句话描述 / 类别标签 / 封面图（可选）/ 链接
- **能力概览区** — 快速展示跨领域技能分布
  - 内容槽：3-4 个领域关键词（量化/AI/写作/开发）/ 每个领域 1 句话描述
- **Footer** — 快速联系 + 社交链接
  - 内容槽：邮箱 / GitHub / LinkedIn / 其他社交链接

### 关于页 `/about`
- **个人介绍区** — 背景故事和职业路径
  - 内容槽：2-3 段个人背景描述 / 头像（可选）
- **技能栈区** — 技术能力明细
  - 内容槽：技能分类（语言/框架/工具）/ 每个技能的熟练度（可选）
- **学习体系区** — 展示持续学习的系统性
  - 内容槽：学习方法论概述 / 在读/在学的方向
- **经历时间线区**（可选） — 关键经历节点
  - 内容槽：时间点 / 事件 / 简述

### 作品集列表 `/projects`
- **筛选/分类区** — 让访客按兴趣找内容
  - 内容槽：类别标签（代码项目 / Principles / Writing / 量化研究）
- **项目网格区** — 所有项目卡片
  - 内容槽：每个项目的标题 / 一句话描述 / 类别标签 / 日期 / 封面图（可选）

### 作品详情 `/projects/[slug]`
- **内容区** — 项目/文章完整内容
  - 内容槽：标题 / 日期 / 类别 / 正文（Markdown 渲染）/ 相关链接（GitHub repo / 外部链接）
- **导航区** — 上一篇/下一篇 + 返回列表

### 联系页 `/contact`
- **联系信息区** — 直接展示联系方式
  - 内容槽：邮箱地址 / GitHub / LinkedIn / 其他社交链接
- **简短引导文案** — 一句话说明什么情况下欢迎联系
  - 内容槽：引导文案（1-2 句）

## 6. 目标衡量

**主指标（上线后 90 天）：**
- 网站成功部署并有稳定访问量（具体数字不设硬门槛，有人访问即达标）

**漏斗指标（过程指标）：**
- 到达首页 → 有访问
- 浏览作品（看 2+ 件）→ 有深度浏览
- 进入联系页 → 有转化意图
- 实际联系 → 最终转化

## 7. 范围
**这一版会做：** 首页 / 关于 / 作品集（列表+详情）/ 联系页 / Obsidian 内容迁移 / GitHub 部署 / 响应式适配

**这一版不做：** 复杂动效 / 评论互动 / 多语言 / 暗色模式 / CMS 后台 / 数据分析 dashboard / 用户系统

## 8. 风险与待解决问题

**已知常见项：**
- 域名是否已注册/选好（还是先用 GitHub Pages 默认域名？）
- Obsidian Markdown 格式与网站渲染的兼容性（双向链接 `[[]]`、callout 等语法需要处理）
- 内容素材是否完备（作品封面图、头像、项目描述等）
- SEO 元信息（meta description、OG image）谁来写
